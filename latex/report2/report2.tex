\section*{Implementation} %{{{1

I have implemented a Binary and Grayscale Line Detection pipeline in the following way:

\begin{itemize}
	\item Smooth the image using a varying Gaussian kernel.
	\item Compute the Edge Magnitude image using horizontal and vertical Sobel kernels.
	\item Apply thresholding from pixel value 75.
	\item Compute the \textbf{Normalized} Hough Transform using a fixed resolution of 512 pixels.
		I decided to use the normalized variant because the wideness of the tram image caused
		most vertical lines to not pass the peak threshold and be lost. My implementation also
		makes no distinction between the grayscale and binary implementation. Binary images will simply
		accumulate values of 255 for every pixel. Because peak-finding is relative to the max, this does not yield
		different results compared to incrementing by 1. Also, normalization evens out these differences in scale either way.
	\item Perform Hough Peak finding with a peak threshold at 50\% and varying Binary Closing kernel size.
	\item Perform Line Segment Detection with varying minimum line intensity, minimum line length and
		maximum gap length. In the line tracing code, I have decided to take the largest edge
		intensity in a neighborhood of 3x3 around the current pixel, to make it compatible with
		Canny Edge Detection which outputs only 1-pixel thin lines. This approach yields more stable
		lines for low-resolution images.
	\item Draw the line segments in \textbf{Red} on top of a darkened version of the original edge image (30\% brightness).
\end{itemize}

\section*{Task 1 | Binary Line Detection} %{{{1

See Figure \ref{fig:task1}. A high minLen ($\geq 64$) results in better and more consistent edges for the tram,
because it has several long horizontal lines that can make use of it. Comparing the images
for $\text{minLen} = 64$ and $\text{minLen} = 128$, the key difference is that the latter 
has ignored most smaller edges, and that it fused longer lines into one due to a slightly bigger gap (8 versus 4).

I have also experimented with the size of the Binary Closing kernel, and found that it is generally
better to leave it at a higher value ($\geq 15$) to prevent many similar and parallell lines in
the output. But for the third image this had little impact due to the small number of overlapping lines.

For the second image, the reduced minimum length allowed more lines on the interior of the tram.
Paired with a much larger maxGap, these lines could jump over the small gaps between the door lines.
Due to the low closing kernel, many parallell lines remain.

I would pick the third image as the cleanest of the three due to it capturing both the
main shape of the tram, some vertical lines corresponding to doors, and the two diagonal lines
corresponding to the front cabin. It also has the least number of lines, making it the simplest.

\section*{Task 2 | Grayscale Line Detection} %{{{1

See Figure \ref{fig:task2}. A big noticeable difference between the Binary and Grayscale pipelines is that

grayscale includes far more sporadic edges as a consequence of high-intensity and high-frequency regions of
blurred lines. In the first Grayscale image, you can see that many diagonal lines are rendered
in places with a high average magnitude (bright spot). This is both a strength and a weakness of
the Grayscale pipeline, because less edges tend to be lost due to thresholding.

In the Binary pipeline, many edges around the tram head are clipped due to the thresholding.
In the Grayscale pipeline, almost all three images contain one or more well fitted edges around 
the tram head.

In all three Grayscale edge images, I have kept all parameters except the blurring factor the same.
This is because the Grayscale pipeline is most susceptible to noise because it does not threshold away any
weak edges. In my opinion an optimal result is obtained for the image with gaussian kernel size 7 (middle).
This image shows both a strong fit on the key horizontal tram edges, and several more decent edges on 
tram head and doors. This makes it on par, or even better than the third image in the Binary pipeline.
It has a moderate blur that smoothens out high-frequency edges, while still retaining a high edge magnitude
that allows the Hough Transform to detect them, contrary to the third image with kernel size 11.
Minimum length was kept high similar to the Binary pipeline, this removed many of the smaller, sporadic edges.
